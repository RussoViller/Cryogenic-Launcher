=====================================================================
  CRYOMOD TUTORIAL — How to make Launcher Mods (.cmod)
  Cryogenic Launcher (r1.8.0+) · CryoMod API v2
=====================================================================

A .cmod is a mod for the Cryogenic Launcher ITSELF (not a Minecraft
mod). It adds ONE new feature to the launcher: a Bedrock -> Java map
converter, a world organizer, a downloader, a farm calculator... and,
since API 2, it can also run INSIDE THE GAME: draw over the game,
press keys, move the mouse, type in the chat, read the game log, add
Java/Minecraft launch arguments (even a -javaagent). The only limit is
your creativity.

In the launcher:
  - Install: Settings > Launcher > Launcher Mods > Import .cmod
  - Enable/disable/delete: in the same window (tap the mod in the list).
  - Use: the "CryoMods" button in the sidebar (same area as WebPage
    and Donation). The mod's feature shows up in the list on the left;
    you can find it by name with the search bar at the top.
  - Enabled mods are kept by "Save Settings".

To try it right now: install CryoMod-Example.cmod (in the root of this
repository), enable it and open the CryoMods page. For the API 2
features (in-game HUD, quick command, auto-walk, chat alerts), install
CryoMod-CryoHUD.cmod and open a game.

---------------------------------------------------------------------
 1. WHAT YOU NEED
---------------------------------------------------------------------

  - JDK 17 or newer (javac and jar).
  - Android SDK with a "platform" (android.jar) and "build-tools" (d8).
    The easiest way is to install Android Studio, or just the Android
    command-line tools.
  - This repository (the build script uses the API in
    CryogenicLauncher/src/main/java/com/russoviller/cryogenic/cmod/api).
  - Linux, macOS, or Windows with Git Bash/WSL (build.sh is bash).
    On a phone you can use Termux (pkg install openjdk-17 + an
    Android SDK with d8).

Language: Java (recommended) or Kotlin. The mod is compiled to
classes.dex, the same format Android apps use.

---------------------------------------------------------------------
 2. QUICK START (copying the example)
---------------------------------------------------------------------

  1) Copy the folder  cmod-sdk/example  to  cmod-sdk/mymod
  2) Edit  cmod-sdk/mymod/cmod.json  (see section 3)
  3) Rename the package/class in  cmod-sdk/mymod/src/...
     (the folder path must match the Java "package")
  4) Replace icon.png (square, 128x128 is a good size)
  5) Build:
        cd cmod-sdk
        ANDROID_HOME=/path/to/android-sdk ./build.sh mymod
     Output: cmod-sdk/out/<id>.cmod
  6) Send the .cmod to your phone and import it in the launcher.

---------------------------------------------------------------------
 3. .cmod FILE STRUCTURE
---------------------------------------------------------------------

A .cmod is a ZIP containing:

  cmod.json      (required) mod info
  classes.dex    (required) compiled code
  classes2.dex.. (optional) if the code is large
  icon.png       (optional) mod icon
  assets/        (optional) your extra files (texts, images, tables,
                            models...). They end up in
                            api.getModDirectory()/assets/
  game/          (optional, API 2) files for the game side, e.g. a
                            Java agent .jar used in "jvmArgs".

Any other file in the zip is ignored. Maximum size: 64 MB.

cmod.json:

  {
    "id": "yourname.mymod",
    "name": "My Mod",
    "version": "1.0.0",
    "author": "Your Name",
    "description": "What the mod does, in one sentence.",
    "main": "com.yourname.mymod.MyMod",
    "apiVersion": 1
  }

API 2 adds optional fields:

  {
    ...
    "gameMain": "com.yourname.mymod.MyGameMod",
    "website": "https://...",
    "dependencies": ["othername.othermod"],
    "jvmArgs": ["-Dmymod.enabled=true", "-javaagent:${modDir}/game/agent.jar"],
    "gameArgs": ["--quickPlayMultiplayer", "play.example.net"],
    "apiVersion": 2
  }

  id          2 to 64 characters: letters, numbers, _ . -
              Use something unique (e.g. yourname.modname). Importing
              another .cmod with the same id UPDATES the installed mod.
  main        Main class (package + name). It must implement CryoMod
              and have a public no-argument constructor. Optional if
              the mod has "gameMain" (a mod only for the game).
  gameMain    (API 2) In-game class: implements CryoGameMod. See 15.
  website     (API 2) Link shown in Launcher Mods (Website button).
  dependencies (API 2) ids of mods that must be enabled first. If one
              is missing, the mod shows "Missing dependency: <id>".
  jvmArgs     (API 2) Extra Java arguments for the game. Only -D..,
              -X.., -javaagent:.., --add-opens, --add-exports and
              --enable-native-access. See 16.
  gameArgs    (API 2) Extra Minecraft arguments (end of the command).
  apiVersion  API version the mod uses. If it is higher than the
              launcher's, the mod won't start ("Failed to start").

---------------------------------------------------------------------
 4. THE MAIN RULE: ONE FEATURE PER MOD
---------------------------------------------------------------------

Each mod adds ONE feature (one button on the CryoMods page).

  api.addButton(...)  with a new id        -> creates the feature
  api.addButton(...)  with the SAME id     -> updates it (title, icon...)
  api.addButton(...)  with ANOTHER id      -> IllegalStateException

Want several tools? Put them all inside your feature's screen (tabs,
cards, buttons). Or make separate mods.

---------------------------------------------------------------------
 5. MINIMAL CODE
---------------------------------------------------------------------

  package com.yourname.mymod;

  import com.russoviller.cryogenic.cmod.api.*;
  import android.widget.LinearLayout;

  public final class MyMod implements CryoMod {

      @Override
      public void onEnable(CryoModApi api) {
          api.addButton(new CryoModButton(
                  "mymod",                  // feature id
                  "My Mod",                 // name in the list
                  "What it does",           // small text (can be null)
                  null,                     // icon (null = the mod's icon.png)
                  screen -> {               // when the button is tapped
                      CryoModUi ui = screen.getUi();
                      LinearLayout page = ui.column();
                      page.addView(ui.title("Hello!"));
                      page.addView(ui.button("Tap here",
                              v -> api.toast("It works!")));
                      screen.setContent(ui.scroll(page));
                  }));
      }

      @Override
      public void onDisable() {
          // stop your own threads/timers here. The button is removed
          // automatically.
      }
  }

Lifecycle:
  onEnable  -> when the mod is enabled, and every time the launcher
               opens with it enabled. Keep it fast (nothing heavy here).
  onDisable -> when the user disables or deletes the mod.
  On button tap -> action.onClick(screen) runs on the main thread.

---------------------------------------------------------------------
 6. THE API (com.russoviller.cryogenic.cmod.api)
---------------------------------------------------------------------

CryoModApi (received in onEnable):
  getApiVersion()        API version of the installed launcher
  getLauncherVersion()   e.g. "r1.8.0"
  getContext()           application Context
  getModId()             the "id" from cmod.json
  getModDirectory()      installed mod folder (read-only; assets/ here)
  getDataDirectory()     folder to SAVE your mod's data (configs,
                         cache...). Deleted together with the mod.
  getGameDirectory()     the launcher's current .minecraft folder
                         (versions, saves, mods, resourcepacks...).
                         Can be null.
  addButton(button)      creates/updates the mod's feature
  removeButton(id)       removes the feature
  toast(text)            short on-screen message (any thread)
  log(text)              writes to the launcher log (tag CryoMod/<id>)
  runOnUiThread(r)       runs on the main thread
  runInBackground(r)     runs on a background thread

CryoModScreen (received when the button is tapped):
  getActivity()          the launcher's Activity (Views, dialogs,
                         ContentResolver...)
  setContent(view)       shows your View in the mod area
  setTitle(text)         changes the area title
  setHeaderVisible(b)    false = hides the title/close bar and your
                         View fills the whole area (100% your own UI;
                         call screen.close() from your own button)
  close()                closes the mod area
  getUi()                UI pieces in the launcher's style
  pickFile(mimes, cb)    pick a file  -> cb.onResult(Uri or null)
  createFile(name, mime, cb)  create a file to save to -> Uri
  pickFolder(cb)         pick a folder (SAF tree Uri)

CryoModButton(id, title, description, icon, action)
  icon is a Bitmap (can be null). action = screen -> { ... }

---------------------------------------------------------------------
 7. UI: LAUNCHER STYLE OR YOUR OWN
---------------------------------------------------------------------

The mod's UI is made with regular Android Views (TextView, Button,
LinearLayout, ImageView, WebView, Canvas...). You have two options,
and you can mix them:

 A) Launcher style (screen.getUi()):
    Colors follow the COLOR THEME the user picked in the launcher
    (blue, green, pink...). Ready-made pieces:

      ui.column() / ui.row() / ui.card() / ui.scroll(view)
      ui.title(t) / ui.text(t) / ui.caption(t)
      ui.button(t, click)           main button (theme gradient)
      ui.secondaryButton(t, click)  glass button with a border
      ui.input(hint)                text field
      ui.switchButton(t, checked, listener)
      ui.slider(max, value, listener)
      ui.progress(indeterminate)
      ui.divider() / ui.space(dp)
      ui.glassBackground(radiusDp) / ui.gradientBackground(radiusDp)
      ui.getAccentColor(), getAuroraColor(), getBackgroundColor(),
      getSurfaceColor(), getTextColor(), getSecondaryTextColor(),
      getGradientColors(), dp(value)

    Everything ui creates is a regular View: you can change size,
    margins, font, color etc. afterwards.

 B) Your own way:
    Build any View/layout you want and pass it to
    screen.setContent(view). To use the whole area:
    screen.setHeaderVisible(false). You can even draw everything in
    your own View (onDraw) or inflate a layout by hand.

  Note: Jetpack Compose is NOT available to mods (the Compose classes
  inside the launcher are optimized/renamed). Use Views.

---------------------------------------------------------------------
 8. FILES, FOLDERS AND THREADS (IMPORTANT)
---------------------------------------------------------------------

  - NEVER do heavy work on the main thread (reading/writing big
    files, network, converting a map). Use:
        api.runInBackground(() -> {
            ... heavy work ...
            api.runOnUiThread(() -> textView.setText("Done!"));
        });
  - Only touch Views on the main thread (runOnUiThread).
  - Files picked by the user arrive as a Uri (content://).
    Read with:
        getActivity().getContentResolver().openInputStream(uri)
    Write with:
        getActivity().getContentResolver().openOutputStream(uri)
  - Picked folder (pickFolder): use DocumentsContract to list and
    create files inside it.
  - The game folder (getGameDirectory) is a regular File: you can read
    and write it directly (e.g. new File(game, "saves")).
  - Your mod's data: api.getDataDirectory().

---------------------------------------------------------------------
 9. ERRORS
---------------------------------------------------------------------

  - If onEnable throws an exception, the mod shows "Failed to start"
    in the list, with the error message. The launcher doesn't close.
  - Exceptions in the feature tap, in file callbacks and in the
    listeners of the screen.getUi() pieces (button, switchButton,
    slider) are caught: a message appears on screen and the error
    goes to the log. The launcher doesn't close.
  - Listeners YOU attach to your own Views (setOnClickListener
    directly on a View of yours, your own Threads) are NOT protected:
    an error there can close the launcher. Use try/catch in them.
  - Use api.log("...") and check the launcher log to debug.

---------------------------------------------------------------------
10. LIBRARIES
---------------------------------------------------------------------

  - The launcher gives the mod: Android, Java (java.*, javax.*),
    org.json and the CryoMod API.
  - Any other library (e.g. Kotlin, Gson, OkHttp) goes INSIDE your
    .cmod: add the .jar files to the compilation and to d8. The mod
    loads its own classes first, so they don't clash with the
    launcher's.
  - build.sh: put the .jar libraries in a libs/ folder next to src/:
    they are used to compile and are merged into classes.dex.
  - Kotlin: compile with kotlinc to a .jar, add kotlin-stdlib.jar and
    pass everything to d8 (build.sh only compiles Java; adapt it if
    you use Kotlin).

---------------------------------------------------------------------
11. SAFETY AND GOOD PRACTICES
---------------------------------------------------------------------

  - A .cmod runs code inside the launcher (and, with gameMain or
    jvmArgs, inside the game), with the same permissions as the
    launcher. Only install mods from people you trust, and
    don't make mods that steal data, accounts or files: the launcher
    shows this warning to everyone.
  - Don't touch the user's files without them asking (show what you
    are going to do and ask for confirmation before deleting or
    overwriting anything).
  - Back up before converting/changing worlds.
  - Keep the "id" the same between versions so the mod updates
    correctly.
  - Change "version" on every release.

---------------------------------------------------------------------

Send the AI:
  1) This file (CryoMod-Tutorial.txt)
  2) All the API files:
       CryogenicLauncher/src/main/java/com/russoviller/cryogenic/cmod/api/
       (CryoMod, CryoModApi, CryoModButton, CryoModScreen, CryoModUi,
        CryoModPrefs, CryoModTask, CryoModInfo, CryoModMessageListener,
        CryoLauncherListener, CryoGameMod, CryoGameApi,
        CryoGameLogListener, CryoKeys)
  3) The examples: cmod-sdk/example/ and cmod-sdk/example-hud/

And a request like:

  "Create a Launcher Mod (.cmod) for Cryogenic Launcher using the
   CryoMod API v2 from the attached files. Java 8, Android Views only
   (no Compose), ONE feature only (one addButton). Heavy work in
   api.runInBackground. Use screen.getUi() for a launcher-style UI.
   The mod must: <describe what you want>. Give me the cmod.json and
   the .java files in the right folder structure so I can build it
   with cmod-sdk/build.sh."

Then build it with build.sh (section 2) and test it in the launcher.

13. BUILDING WITHOUT build.sh (manual)
---------------------------------------------------------------------

  # 1) API (only to compile against; it does NOT go inside the .cmod)
  javac -source 8 -target 8 -cp $ANDROID_JAR -d api_classes \
        <api folder>/*.java
  # 2) your code
  javac -source 8 -target 8 -encoding UTF-8 \
        -cp $ANDROID_JAR:api_classes -d classes $(find src -name '*.java')
  jar cf mod.jar -C classes .
  # 3) dex
  d8 --release --min-api 26 --lib $ANDROID_JAR \
     --classpath api_classes --output dex mod.jar
  # 4) package (zip with cmod.json, classes.dex, icon.png, assets/, game/)
  cp cmod.json icon.png dex/
  (cd dex && zip -r ../mymod.cmod .)

14. API 2: MORE POWER IN THE LAUNCHER
---------------------------------------------------------------------

Set "apiVersion": 2 to use these (launchers with API 1 won't load the
mod). All of them are on CryoModApi:

  getPreferences()        key/value settings (getString/putInt/...),
                          saved right away and SHARED with the in-game
                          side of the mod.
  schedule(ms, r)         run later on the main thread.
  scheduleRepeating(..)   run every N ms. Both return a CryoModTask
                          (cancel()) and stop when the mod is disabled.
  setButtonBadge("3")     small badge on your button (null removes).
  openUrl / copyToClipboard / shareText
  getLanguage()           "pt", "en", "zh"... (translate your mod)
  getInstalledMods()      CryoModInfo of every installed mod.
  isModEnabled(id)
  getGameVersions() / getSelectedGameVersion() / selectGameVersion()
  addLauncherListener(..) events: onGameLaunch(version),
                          onLauncherForeground/Background,
                          onModEnabled/Disabled, onGameVersionSelected.

Mods talking to mods:

  api.sendMessage("other.mod", "channel", payload)  -> one mod
  api.broadcast("channel", payload)                  -> every mod
  api.addMessageListener((from, channel, payload) -> { ... });

  api.exposeService("name", object)      share an object
  api.getService("other.mod", "name")    get it from another mod

  Each mod has its own class loader: share objects whose types come
  from Android/Java (Runnable, Map, java.util.function.*, String...).
  With "dependencies" you can build library mods used by other mods.

New UI pieces (screen.getUi()): image, chip, checkbox, choice
(dropdown), listItem, grid, confirm, prompt and dialog (any View in a
themed dialog).

The Launcher Mods window shows, for each mod: status, what it does
(Launcher / In-game / JVM args / Game args), id, version, size,
dependencies, and the buttons Restart (reloads the .cmod from disk:
great while developing), Logs (everything api.log wrote, plus the
last game session), Share (exports the .cmod), Website, Clear data
and Delete.

---------------------------------------------------------------------
15. API 2: IN-GAME MODS (gameMain)
---------------------------------------------------------------------

The class in "gameMain" implements CryoGameMod and runs in the game
screen (a different process from the launcher: share data with
getPreferences(), not with static fields).

  public final class MyGameMod implements CryoGameMod {
      @Override
      public void onGameStart(CryoGameApi api) {
          TextView pill = api.getUi().chip("Hello!", true, null);
          api.addOverlayView(pill, Gravity.TOP | Gravity.END, 12, 10);
          api.addLogListener(line -> {
              if (line.contains("[CHAT]") && line.contains("!day"))
                  api.sendChatMessage("/time set day");
          });
      }
      @Override
      public void onGameExit(int exitCode) { }
  }

CryoGameApi:

  getOverlay() / addOverlayView(view, gravity, xDp, yDp) /
  removeOverlayView(view)
      A layer over the game AND the controls. Empty areas let the
      touch through; only clickable Views catch touches.
  pressKey(key, down) / tapKey / holdKey(key, ms) / typeText(text)
  mouseButton(button, down) / click / setCursor / moveCursor / scroll
      Keys use GLFW codes: CryoKeys.W, CryoKeys.SPACE, CryoKeys.F3,
      CryoKeys.MOUSE_LEFT...
  sendChatMessage("/command or text")
      Opens the chat, types and sends. Only while playing (no menu
      open): returns false otherwise.
  isCursorGrabbed()   true while playing (no menu/inventory/chat).
  getFps(), getWindowWidth(), getWindowHeight(), getCursorX/Y()
  addLogListener(line -> ...)
      Every line of the game log. Chat messages contain "[CHAT]".
      Runs on the log thread: be quick.
  getVersionName(), getMinecraftVersion(), getGameDirectory()
  getPreferences(), getUi(), toast, log, runOnUiThread,
  runInBackground, schedule, scheduleRepeating

Tip: macros (holdKey + click in sequence), auto-walk, timers, chat
bots, stream alerts, a HUD with anything you calculate, a button
that runs your favorite commands... all of this is possible.

---------------------------------------------------------------------
16. API 2: JVM AND GAME ARGUMENTS
---------------------------------------------------------------------

"jvmArgs" are added to the Java of the game when it starts; "gameArgs"
are added to the end of the Minecraft arguments. Placeholders:

  ${modDir}    folder of the installed .cmod (game/ files are there)
  ${dataDir}   data folder of the mod
  ${gameDir}   game folder of the running version

Example: a Java agent that changes Minecraft classes while it loads
(the agent .jar is normal Java, compiled for the game's Java):

  "jvmArgs": ["-javaagent:${modDir}/game/myagent.jar=${dataDir}"]

The arguments only apply while the mod is enabled. They are written in
the game log ("CryoMods: JVM args ...").
